# 로그 분석 리포트 작성 가이드

> Log Analysis Report — Writing Guide v2.1
> 본 가이드는 `로그분석_리포트_템플릿.md`의 필드별 작성 규칙을 정의한다.
> 분류 기준의 정의와 근거는 `로그분석_분류체계_정의서.md`를 따른다.

---

## 0. 공통 규칙

- 분석 범위는 SW(Kernel Driver)로 한정한다. 단, 결함 판정의 범주는 SW로 한정되지 않는다.
- **판정은 단일 선택, 조치는 복수 선택 가능**하다. 복합 케이스(예: 이관/외부 대응 + 방어적 수정)는 조치를 병기한다.
- 조치의 하위 항목에 원인·사유(원인의 성격)를 기재하지 않는다. 사유는 판정(결함영역)이 담는다.

---

## 1. 기본 정보

| 필드 | 작성 규칙 |
|---|---|
| 이슈 번호 / 제목 | 이슈 트래커의 식별자와 제목을 기재 |
| 분석자 / 담당 모듈 | 담당 모듈은 프로필 설정값을 사용 |
| 분석 일자 | 분석 수행일 (YYYY-MM-DD) |
| 로그 출처 / 기간 | 수집 환경, 대상 버전, 로그의 시간 범위를 기재 |

---

## 2. 현상 및 분석

| 필드 | 작성 규칙 |
|---|---|
| 보고된 현상 | 재현 절차·발생 조건이 있으면 함께 기재 |
| 분석 내용 | 핵심 로그 라인, 타임라인, 분석 근거를 요약. **결함영역이 SW(Kernel Driver)인 경우 상세 분석을 기재**하고, SW 외(HW / 환경 / 서드파티 / 검증계)인 경우 근거와 함께 판정 사실만 기재 |

---

## 3. 판정 (Verdict)

| 필드 | 작성 규칙 |
|---|---|
| 판정 | 단일 선택. 결함 / 비결함 / 판정불가 |
| 문제현상 발현 영역 | **결함인 경우 필수.** 현상이 관측된 모듈명 기재 |
| 결함영역 | **결함인 경우 필수.** 원인이 위치한 곳. 특정 모듈(모듈명 기재) / 외부요인(HW·환경·서드파티·고객사 — 올바른 동작에 관여하는 외부 구성 요소) / 검증계(테스트 환경·스크립트·측정 장치 — 동작 관측용, 올바른 동작 구현에 관여하지 않음) 중 선택 |
| 판정불가 사유 | **판정불가인 경우 필수. 단일 선택.** 로그부족 / 재현불가 / 기타(사유 서술 필수) |
| 판정 근거 | 판정을 뒷받침하는 로그·코드·스펙 근거를 기재 |

- 발현 영역과 결함영역을 분리 기재함으로써 "현상은 특정 모듈에서 발현되지만 원인은 다른 곳에 있는" 케이스를 표현한다.
- 비결함의 범위: 스펙(설계 의도)대로의 정상 동작 / 사용자 오해·기대치 차이 / 조치가 불필요한 일회성 이벤트.

---

## 4. 조치 (Action)

구분 기준은 **수정 위치(어디서 해결되는가)**이다. 해당하는 조치를 모두 선택한다.

| 조치 | 적용 조건 | 작성 규칙 |
|---|---|---|
| 수정 및 해결 | 분석 대상 모듈에 코드 변경 발생 | 오류 수정(근본 원인 수정) / 방어적·회피 수정 중 선택. **수정 모듈 기재 필수.** 결함영역과 수정 모듈이 다른 경우(예: 타 영역 결함에 대한 방어적 수정) 좌표 대비로 드러나며, 필요 시 별도 기재 |
| 추가 조치 | 판정을 위한 후속 분석 활동 (주로 판정불가 건) | 로그 추가, 재현 조건 확보, 재발 대기 등 계획을 기재 |
| 유지 | 수정 위치 없음, 종결 | 비결함 종결(예: 오발췌) / 결함 수용·보류(**사유 필수**: 기술적 불가, 우선순위·비용) / 판정불가 종결 |
| 이관/외부 대응 | 해결이 조치 가능한 범주 밖에서 이루어짐 | **해결 주체 기재 필수.** 타 모듈, 고객사, 서드파티, HW 조치, 검증계 담당 등 |

> **건 상태**: 수정및해결 · 추가조치 · 이관/외부대응 = **열린 건**(해결 활동 계속) / 유지 = **닫힌 건**(추가 조치 없음)

---

## 5. 좌표 조합 기록 예시

세 좌표(발현 영역 / 결함영역 / 수정 모듈·해결 주체)와 판정·조치의 조합으로 케이스를 기술한다.

| 케이스 | 기록 방법 |
|---|---|
| 담당 모듈 문제, 수정 진행 | 결함(발현=A, 결함영역=A) + 수정및해결(Fix, 수정 모듈=A) |
| 현상은 담당 모듈, 원인은 타 모듈 | 결함(발현=A, 결함영역=B) + 이관/외부 대응(해결 주체=B 담당) |
| 타 모듈 원인 + 담당 모듈에 회피코드 | 결함(결함영역=B) + 이관/외부 대응(해결 주체=B 담당) + 수정및해결(방어적 수정, 수정 모듈=A) |
| 문제지만 수정 불가 | 결함(결함영역=A) + 유지(사유: 기술적 불가) |
| 서드파티/고객사 원인 | 결함(결함영역=외부요인) + 이관/외부 대응(해결 주체 명기) |
| HW 결함, HW 교체 요청 | 결함(결함영역=외부요인·HW) + 이관/외부 대응(HW 조치) |
| HW 결함, 일회성으로 종결 | 결함(결함영역=외부요인·HW) + 유지 |
| 테스트 스크립트 결함, 담당에 전달 | 결함(결함영역=검증계) + 이관/외부 대응(검증계 담당) |
| 테스트 환경 오발췌 | 비결함 + 유지 |
| 정상 동작 / 사용자 오해 | 비결함 + 유지 |
| 로그 부족으로 결론 불가 | 판정불가(로그부족) + 추가 조치(로그 추가) |
| 재현 안 되어 종결 | 판정불가(재현불가) + 유지 |

*(A = 분석자의 담당 모듈, B = 그 외 특정 모듈. 표기 편의상의 기호이며, 기록은 좌표 값으로만 동작한다.)*
